# Design: Vocabulary Trainer

**Date:** 2026-10-12
**Status:** Approved (design discussion), revised after spec review
**Branch:** `feat/vocab-trainer` (from `main` after PR #11)

## Overview

Kana grows into a vocabulary trainer. Words written in kana fall like tiles; the learner types
the reading in romaji and, after a hit, sees the meaning. Words appear only when the learner
can read them (their kana are known) and only up to the learner's JLPT level. Words come from
a bundled list derived from JMdict with JLPT levels from Jonathan Waller's lists, and from
private word lists the learner keeps in their data directory, never in the repository.

Words need three things the app does not have yet: the small っ/ッ, the long vowel mark ー and
the extended katakana (ティ, ファ, ヴ …). They are added here.

The work ships in four stages, each with its own plan and PR (see Stages).

## Decisions

| Topic | Decision |
|---|---|
| Play forms | **Mixed** (default): words fall among kana tiles. **Words only**: a mode for targeted practice of a level, a private list or one lesson of it. |
| Answer | The romaji reading of the whole word. The meaning is shown after a hit and, with the solution, after a miss. |
| Meaning language | A setting. Bundled words carry all JMdict languages; fallback to English, then to any available language. Private lists carry their own meanings. Input is always Hepburn romaji. |
| Word playable (mixed) | Every kana unit of the word is **secure** (≥ 3 correct, the panel's "mastered") **and** its script is active. |
| Word playable (words only) | Every kana unit is **unlocked** (in an active row of an active script). The learner chose the practice explicitly. |
| っ/ッ and ー | Known in both modes when their script is active; ー is known when either script is active (it also occurs in hiragana readings). |
| Extended katakana | Both: a new katakana-only learning-path group with tiles and intros, and part of words. A word with ティ needs ティ itself to be known. |
| Bundled words | Only words with a JLPT level (about 7,000, N5–N1), shown in their kana reading. No kanji. |
| JLPT level | Setting "Vocabulary up to N5 … N1", default N5. Bundled words above the level are never played. Private lists ignore the level. |
| Level offer | When 90 % of the bundled words of the current level that use only active scripts are secure, a dialog offers the next level. Declined → not asked again for that level. |
| Private lists | CSV/TSV and JSON in `~/.local/share/kana/words/` (honours `XDG_DATA_HOME`). |
| Progress key | Per reading: `word:<kana>` in `memory`, and a `word_stats` row. Homophones (also across sources) share progress; their meanings are merged. |

## Stage 1: Kana extensions and reading match (`kanacore`)

### Extended katakana group

A new group `GroupExtended` ("Extended katakana"), **katakana only**.

| Row ID | Entries (canonical, alternatives) |
|---|---|
| `kata:ext-t` | ティ ti/thi, ディ di/dhi, トゥ tu/twu, ドゥ du/dwu |
| `kata:ext-f` | ファ fa, フィ fi, フェ fe, フォ fo |
| `kata:ext-w` | ウィ wi, ウェ we, ウォ wo |
| `kata:ext-sh` | シェ she/sye, ジェ je/zye/jye, チェ che/tye/cye |
| `kata:ext-v` | ヴァ va, ヴィ vi, ヴ vu, ヴェ ve, ヴォ vo |
| `kata:ext-ts` | ツァ tsa, ツィ tsi, ツェ tse, ツォ tso |

- The rows are defined directly in katakana and appended to `KatakanaRows` after the rows
  generated by `toKatakanaRows`. `RowsFor(Hiragana)` does not contain them.
- `ProgressionStepsFor(Katakana)` appends three steps after the generated ones:
  `{kata:ext-t, kata:ext-f}`, `{kata:ext-w, kata:ext-sh}`, `{kata:ext-v, kata:ext-ts}`.
  Hiragana steps are unchanged.
- New `GroupsFor(s Script) []GroupInfo` returns only the groups that have rows in that script.
  The settings dialog and the status panel use it instead of `Groups()`, so the hiragana tab
  shows no empty "Extended katakana" heading.
- **Status panel:** extended rows do not fit the vowel columns (ティ and ディ are both "i").
  They are shown as an extra katakana-only block below the side-by-side grid, one line per
  row with the entries in order, coloured by learning state like the other cells.
- Input collisions (ティ/ち "ti", トゥ/つ "tu", ウォ/を "wo") need no new rule:
  `checkAnswer` already picks the lowest matching tile.

### Word units

`KanaUnits(word string) ([]string, bool)` splits a word into units, longest match first:

1. a two-character combination known to any row (yōon きゃ, extended ティ);
2. a single kana known to any row;
3. っ/ッ (sokuon) and ー (long vowel mark) as units of their own.

It returns `false` if any character cannot be placed (e.g. ゐ, ヶ, a kanji), and for
sequences that cannot be typed:

- っ/ッ not followed by a unit whose canonical romaji starts with a consonant other than the
  `n` of ん (so a trailing っ, っ before あ, ん or ー fail);
- ー at the start, or right after ん/ン or っ/ッ.

### `ReadingMatches(word, input string) bool`

Input is lowercased and trimmed. It matches when the input can be split, left to right, so
that each unit is matched by one of its spellings:

- A normal unit: its canonical romaji or any alternative from its row (`shi`/`si`,
  `chi`/`ti`, `tsu`/`tu`, `ja`/`zya`/`jya` …).
- ん/ン: `n`, `nn` or `n'`. Because one known word is checked, `n` before a vowel is
  not ambiguous.
- っ/ッ: doubles the first letter of the next unit's chosen spelling (`kitte`); before a
  spelling starting with `ch`, `t` is also accepted (`matcha` and `maccha`).
- ー: repeats the last vowel of the chosen spelling of the nearest preceding unit that is not
  ー (`koohii`), or `-` (`ko-hi-`). So ーー is `oo` or `--` after こ.
- Long vowels written with う/お/い are typed kana by kana: とうきょう is `toukyou`;
  `tokyo` does not match. This is deliberate, so learners notice long vowels.

Implementation: recursion over (unit index, input position) with memoisation; words are short.

### `Romaji(word string) string`

The canonical spelling, built from each unit's canonical romaji with the rules above:
っ doubles the next consonant, but gives `t` before `ch` (`matcha`); ー repeats the vowel
(`koohii`); ん is `n'` before a vowel or y (`kin'en`), else `n`. Used as the solution shown
after a miss.

## Stage 2: Word data (`vocab`, `cmd/vocabgen`)

### Model

```go
type Word struct {
	Kana     string            // reading, e.g. "せんせい"
	Meanings map[string][]string // ISO 639-1 language → {"teacher", "master"}
	JLPT     int               // 5…1, 0 = none
	Source   string            // "jmdict" or a list name, e.g. "minna-no-nihongo"
	Lesson   string            // optional, private lists only
}
```

`vocab` depends on `kanacore` (for `KanaUnits`) and nothing from the app.

### Bundled list

- **Meaning lists:** every meaning field holds a list of alternatives. In input files several
  alternatives share one field, separated by `;` (`Lehrer; Lehrerin`). Loaders split on `;`,
  trim spaces, drop empty and duplicate items (keeping first-seen order). Display joins them
  with "; ". Merging (homophones, sources) appends and de-duplicates the same way. A later
  "type the meaning" mode could accept each item.
- `vocab/data/words.json.gz`, embedded with `go:embed`, loaded by `vocab.Bundled() ([]Word, error)`.
  Format: a JSON array of `{"k": kana, "j": level, "m": {"en": ["…", "…"], "de": […]}}`.
- Generated by `go run ./cmd/vocabgen -jmdict JMdict.gz -jlpt <dir> -out vocab/data/words.json.gz`,
  run by hand, not during build. Inputs are downloaded by the maintainer; the tool does not
  download.
  - JMdict: the full multilingual `JMdict.gz` (EDRDG). Languages kept: en, de, fr, ru, es, hu,
    nl, sv, sl (JMdict codes eng, ger, fre, rus, spa, hun, dut, swe, slv).
  - JLPT levels: Jonathan Waller's lists (tanos.co.uk, CC BY), matched to JMdict entries via
    an existing published mapping (e.g. `stephenmk/yomitan-jlpt-vocab`); its licence is
    checked in stage 2 and recorded in `ATTRIBUTION.md`. If no usable mapping exists, match
    by kanji form + reading.
  - **Reading:** the reading the JLPT list (or mapping) gives for the row; rows without a
    reading or without a JMdict sequence number are skipped and counted.
  - **Gloss cleanup** (gentle: strip clear markup, drop what cannot be made plain, never
    guess). English glosses are kept as they are. Every gloss, English included, is split on
    `;` like a private list's meanings (a `;` inside parentheses becomes `,`), so meaning
    items never contain `;`; the split items count towards the caps below. A non-English
    gloss with `~` or `～` outside a marker of the word's own grammatical form (`{～な}`,
    `{～の}`, `{～する}` …) is the meaning of a derived phrase and dropped whole. Each
    non-English item is then cleaned: leading numbering (`1) `, `1. `, `а) `, `: `), form
    markers and `(…)` labels are stripped, repeatedly and in any order; a trailing
    source-language note (`(eng: scene)`, `(ger)` …) is stripped; other `{…}` clarifications
    become `(…)` (`moški {formalno}` → `moški (formalno)`). An item is dropped if it then
    starts with `(` or `-`, has unbalanced parentheses, stray braces, kana or kanji, or is
    shorter than two characters.
  - **Meanings:** per language, the glosses of the first sense that has glosses in that
    language (in JMdict, non-English glosses sit in their own senses), at most three.
  - Entries whose reading fails `KanaUnits` are dropped and counted in the tool's output.
  - Entries with the same reading are merged into one word: the easiest level (the highest
    number, e.g. N5 over N3) wins; meanings are merged per language (de-duplicated), at most five
    glosses per language.
- `vocab/data/ATTRIBUTION.md`: JMdict © Electronic Dictionary Research and Development Group,
  CC BY-SA 4.0; JLPT levels © Jonathan Waller, CC BY, unofficial (no official JLPT lists
  exist since 2010); the mapping's source and licence. The data file is an adaptation under
  CC BY-SA 4.0; the code stays MIT. The README gains a "Word data" section with the same
  attribution and links to the file. This stage merges before stage 3, so the attribution
  is in place before the app uses the data.
- **Regular updates (EDRDG licence):** "there must be a procedure for regular updating of the
  data from the most recent versions available". `.github/workflows/update-words.yml` runs
  monthly (and on demand), regenerates `words.json.gz` from the latest JMdict and mapping,
  records the inputs in `vocab/data/SOURCES`, and opens a PR `fix(vocab): update word data
  from JMdict` when the data changed, so release-please cuts a patch release.

### Private lists

- Directory: `filepath.Join(dataDir, "words")`, where `dataDir` is the directory of
  `store.DefaultPath()`. Not created automatically (only by "Open folder" in stage 4).
  `.gitignore` gains `words/` as a guard.
- `vocab.LoadDir(dir string) ([]List, error)`; a missing directory returns no lists and no
  error. Each `List` has `Name`, `Words []Word` and `Problems []string` (at most the first 10,
  plus a count of skipped rows).
- **Names:** the file name without extension. If two files share it (`a.csv`, `a.json`), both
  get the extension appended (`a (csv)`, `a (json)`). `jmdict` is reserved: a file
  `jmdict.csv` is named `jmdict (csv)`.
- **CSV/TSV** (`*.csv`, `*.tsv`): UTF-8, a BOM is ignored. The header row is required; the
  separator is detected from it: tab, then semicolon, then comma. Columns (case-insensitive):
  `kana` (required), `meaning` (applies to every language not given separately),
  `meaning_<lang>`, `lesson`, `jlpt` (accepts `5` or `N5`). A file without a `kana` column is
  one problem and no words. A row whose `kana` fails `KanaUnits` is skipped with a problem
  "line 17: 先生 is not kana".
  A field containing the file's separator must be quoted, as usual for CSV: in a
  semicolon-separated file `せんせい;"Lehrer; Lehrerin";teacher;1` (spreadsheet programs do
  this when saving).
- **JSON** (`*.json`): an array of `{"kana": …, "meaning": "…" or {"de": …}, "lesson": …,
  "jlpt": …}`; a meaning value may also be an array of strings, and strings are split on `;`
  like CSV fields. Same row rules; unparsable JSON is one problem and no words.
- Within one list, duplicate readings are merged like bundled homophones.

### Word index

```go
// Index merges words from several sources into one entry per reading.
// Meanings are merged per language; Sources and Lessons collect every origin;
// JLPT is the easiest bundled level (0 if the reading comes only from private lists).
func NewIndex(bundled []Word, lists []List) *Index

func (ix *Index) Entries() []Entry          // all readings
func (ix *Index) Lookup(kana string) (Entry, bool)
```

`Entry` has `Kana`, `Meanings`, `JLPT`, `Bundled bool`, `Lists map[string][]string`
(list name → lessons). Game code works on entries, so a reading appears once even when the
bundled list and a private list both contain it.

### Playable filter

```go
// Playable returns the entries whose units all satisfy known and which pass
// the source filter.
func Playable(entries []Entry, known func(unit string) bool, filter Filter) []Entry

type Filter struct {
	MaxLevel int    // bundled entries need JLPT >= MaxLevel numerically (5 = N5 only)
	List     string // "" = bundled up to MaxLevel plus every private list (mixed mode);
	                // "jmdict" = bundled entries only, up to MaxLevel;
	                // else only this private list, level ignored
	Lesson   string // with a private List: only this lesson ("" = all)
}
```

An entry from a private list passes regardless of level. In words-only mode `word_source`
maps directly onto `Filter.List`.

`NewIndex` computes each entry's units once (`Entry.Units []string`); `Playable` and the level
offer use them instead of calling `KanaUnits` again.

## Stage 3: Words in the game (mixed mode)

### Store

- New table, created in `migrate`:
  ```sql
  CREATE TABLE IF NOT EXISTS word_stats (
  	kana          TEXT PRIMARY KEY,
  	correct_count INTEGER NOT NULL DEFAULT 0,
  	miss_count    INTEGER NOT NULL DEFAULT 0
  );
  ```
  Separate from `kana_stats`, because the word か (mosquito) must not share the character か's
  stats.
- `WordStatistics() (map[string]WordStats, error)` and `SaveWordStats(kana string, correct,
  miss int) error` (absolute values, upsert), mirroring the kana path.
- Settings keys with defaults when unset: `word_level` (5), `meaning_lang` (system language
  if one of the nine JMdict languages, else `en`). Stage 4 adds the UI for them.

### GameState

- **Words:** loaded once in `NewGameState`: `vocab.Bundled()` plus `vocab.LoadDir(wordsDir)`,
  merged with `vocab.NewIndex`. A bundled load error disables bundled words; the status line
  then shows "Words unavailable: <error>". Kana play is unaffected.
- **Stats:** `wordOverallStats` and `wordSessionStats` (correct, miss per reading) with their
  own `wordSessionDirty` flag. `mergeSessionStats` merges them independently of the kana
  stats: its own baseline read (`WordStatistics()`), its own early return, so a skipped or
  failed kana merge does not skip the words (and vice versa). Reloaded in `Reset` like the
  kana stats. A word is secure when overall + session correct ≥ 3.
- **Memory:** a separate `wordMemory map[string]memory.State` and `wordMemoryDirty`, loaded
  with `MemoryStates("word:")`, with their own `wordMemoryLoadFailed` flag. `saveMemory` also
  writes dirty word states as `"word:"+kana`, unless that flag is set.
- **Tiles:** a tile carries either a kana or a word (`tile.word *vocab.Entry`, nil for kana).
  Code that reads `tile.kana` branches on `tile.word`: `spawnCandidates` (falling kana) and
  the falling-words exclusion each look only at their own kind; `dropInactiveTiles` removes a
  word tile when the word is no longer playable.
- **Known (mixed):** see Decisions. The unit's correct count is the kana's overall + session
  count; its script comes from the row that contains it.
- **Spawn:** with `p = min(0.3, len(playable) / 100)` (decided with `gs.rnd`), a spawn is a
  word; otherwise a kana as today. The word is chosen with `memory.Pick` over the playable
  readings, excluding readings already falling (unless none remain), with `wordMemory`,
  `gs.now()` and `gs.rnd`.
- **Fall time:** level range × tempo × `min(1 + 0.2 × (units − 1), 2)`. The per-character
  factor does not apply to words.
- **Answer:** `checkAnswer` tests kana tiles with `Matches` and word tiles with
  `ReadingMatches`; the lowest matching tile wins. A word hit scores `10 × units ×
  pointsFactor()`, records a word correct (session stats, memory, answer streak and tempo as
  for kana). It does not change any kana's stats.
- **Miss:** `tick` branches on `tile.word`. A missed word counts towards the miss limit,
  records a word miss (session stats, `memory.Miss` when it has a state), lowers the tempo
  like a kana miss and is appended to `missedWords`. The game-over dialog lists missed words
  as "せんせい (sensei)" below the missed kana; `missReason` becomes "N tiles slipped through."
- **Feedback:** a list of feedback labels, each with text, position, kind (hit or miss) and
  `ticksLeft = 20` (2 s at 100 ms ticks). `tick()` counts them down, so they freeze while
  paused. After a hit: "はい — yes" at the tile's last position. After a miss:
  "はい · hai — yes" at the bottom in the error colour. They are part of the snapshot, hidden
  whenever tiles are hidden, and cleared by `Reset`. The meaning comes from `meaning_lang`,
  then `en`, then any language; a word without meanings shows only kana (and romaji for a
  miss). Long meanings are truncated for display: at most the first 3 items, and an ellipsis
  past about 60 characters.
- **Word tiles:** a distinct face colour and border, so a one-unit word (か) does not look like
  a kana tile. Width is text plus padding; if wider than the field, the font shrinks to fit.
  The spawn x-position keeps the tile inside the field.
- **Status panel:** a line "Words: 42 playable · 17 secure · up to N5" (in words-only mode it
  names the source instead of the level), or the "Words unavailable" message.
- **Sources:** until the stage 4 tab exists, the status panel shows a small line "Word data:
  JMdict (EDRDG, CC BY-SA 4.0), JLPT levels by J. Waller", so the app attributes the data it
  uses from the first release that uses it.

## Stage 4: Words-only mode, settings, level offer

### Words-only mode

- Setting `game_mode`: `mixed` (default) or `words`.
- Setting `word_source`: `jmdict` (default) or a list name; `word_lesson`: empty (all) or a
  lesson value of that list.
- In words mode every spawn is a word from the chosen source (and lesson) by the **unlocked**
  rule, chosen with `memory.Pick` over `wordMemory`. With no playable word, kana spawn instead
  and the status line says "No playable words — unlock more kana or pick another list".
- If the stored `word_source` no longer exists, `jmdict` is used and the Words tab says so.

### Level offer

- Settings `word_level` (from stage 3) and `word_level_declined` (the level number that was
  offered and declined, 0 = none).
- After a word hit, when not over, `word_level > 1`, `word_level_declined != word_level − 1`,
  at least one bundled word of level `word_level` uses only active scripts, and at least 90 %
  of those words are secure, the offer "Add N<level−1> vocabulary?" is queued.
- Pause invariant, as for the katakana offer:
  - a `pendingLevelOffer` field, set only when the `levelOfferEvent` send succeeds;
  - `settle()` keeps the game paused while it is set;
  - `PendingDialogs` reports it, and `showPendingDialogs` shows it after the katakana offer
    and before intros;
  - `Reset` clears it;
  - `watchEvents` (app.go) calls `showPendingDialogs` for `levelOfferEvent` as it does for
    `rowsUnlockedEvent` and `katakanaOfferEvent`, dropping it when the game is over.
- `AcceptLevelOffer()` lowers `word_level` by one; `DeclineLevelOffer()` stores
  `word_level − 1` in `word_level_declined`. Each clears `pendingLevelOffer`, saves, and calls
  `settle()`. Changing the level by hand does not touch `word_level_declined`.

### Settings dialog

The dialog gets four outer tabs; it must still fit the 1000 × 760 window:

| Tab | Content |
|---|---|
| Kana | today's scripts row, per-script row tabs (groups via `GroupsFor`) and auto-progression |
| Words | mode, level (N5–N1), source and lesson (words-only), meaning language, private lists with word count and problems, "Reload lists", "Open folder" |
| Game | difficulty, points per hit, score limit |
| Sources | attribution for JMdict, Waller (unofficial levels) and the mapping, with licences and links |

- The meaning-language choice lists the nine JMdict languages plus any `meaning_<lang>` found
  in private lists.
- "Reload lists" re-reads the directory and rebuilds the index; "Open folder" creates it if
  missing and opens it via `fyne.CurrentApp().OpenURL`.
- The stage 3 attribution line in the status panel is removed once the Sources tab exists.

## Testing

- **kanacore (stage 1):**
  - `KanaUnits`: きゃく, パーティー, ヴァイオリン, きって succeed; 先生, ゐ, a leading ー,
    a trailing っ (あっ), っ before a vowel or ん, ー after ん or っ fail.
  - `ReadingMatches` table: きって `kitte`; まっちゃ `matcha`/`maccha`; コーヒー
    `koohii`/`ko-hi-`/`ko-hii`; でんしゃ `densha`/`densya`/`dennsha`/`den'sha`; きんえん
    `kinen`/`kin'en`/`kinnen`; パーティー `paatii`/`paathii`; とうきょう `toukyou` yes,
    `tokyo` no; ふじさん `fujisan`/`huzisan`; wrong inputs, a prefix and an overlong input
    do not match.
  - `Romaji` for the same words (`kin'en`, `matcha`).
  - The katakana steps end with the three extended steps; hiragana steps and rows are
    unchanged; `GroupsFor(Hiragana)` has no extended group.
  - Settings and panel: the hiragana tab has no extended heading; the panel shows the
    extended block for katakana.
- **vocab (stage 2):**
  - CSV with comma, semicolon and tab; BOM; missing `kana` column; non-kana rows reported;
    `meaning` vs `meaning_de`; `jlpt` as `4` and `N4`; `"Lehrer; Lehrerin"` quoted in a
    semicolon-separated file gives two German meanings; duplicates and empty items dropped.
  - JSON with meaning as string and as object; broken JSON.
  - Name collisions and the reserved `jmdict` name.
  - Homophones merged within a list and across sources in `NewIndex`.
  - `Playable` with level, list and lesson filters; private words ignore the level;
    `List: "jmdict"` returns only bundled entries up to the level; `Entry.Units` is set.
  - `Bundled()` loads, has more than 5,000 words, and every word passes `KanaUnits`.
  - `LoadDir` on a missing directory returns nothing and no error.
- **store (stage 3/4):** `word_stats` and every new setting round-trip and default.
- **fyne (stage 3):**
  - Word share with a seeded `rnd`: 0 with no playable word, about 0.3 with ≥ 30.
  - Known rule: a katakana word stops being playable when katakana is turned off.
  - Word tile fall time, points, hit and miss (session stats, memory, miss limit, tempo,
    `missedWords`), merge persists word stats and word memory, also when only words changed
    or the kana baseline read fails.
  - A kana tile and a word tile both matching: the lower one wins.
  - Feedback labels expire after 20 ticks, freeze while paused, are hidden with tiles and
    cleared by `Reset`.
  - Status line text, including "Words unavailable".
- **fyne (stage 4):**
  - Words-only: unlocked rule, list and lesson filter, kana fallback with the hint, missing
    source falls back to `jmdict`.
  - Level offer at 90 % (counting only words of active scripts), not with zero qualifying
    words, not after a decline of that level, not when over; the event leads to the dialog;
    with the offer pending and the settings dialog closed the game stays paused; Accept and
    Decline clear it and resume; `Reset` clears it.

## Stages

1. **Kana extensions:** extended katakana group (rows, steps, `GroupsFor`, panel block),
   `KanaUnits`, `ReadingMatches`, `Romaji`. Playable result: the new katakana group.
2. **Word data:** `vocab` (model, loaders, index, filter), `cmd/vocabgen`, the bundled list,
   `ATTRIBUTION.md` and the README section. No UI.
3. **Words in the game:** mixed mode, `word_stats`, `word_level`/`meaning_lang` keys, word
   tiles, feedback, missed words, status line with the attribution line.
4. **Words-only mode and settings:** tabs, private lists in the UI, level offer, Sources tab.

Each stage gets its own plan and PR, merged in order.

## Out of Scope

- An Anki loader (`.apkg`: a zip with a SQLite collection, newer exports zstd-compressed) with
  a per-deck field mapping. It would return `vocab.List` values. Anki's plain-text export
  (tab-separated) already works through the TSV loader.
- Other input systems (Polivanov Cyrillic, kana input via IME). They would replace the
  romaji spellings used by `ReadingMatches`.
- A translated UI.
- Kanji and furigana; asking for the meaning instead of the reading.
- Thierry Bézecourt's pre-2010 JLPT lists (no free licence) and Wagotabi's own data
  (proprietary).
